# SXSVN Intelligence

Сервис мониторинга новостей для компаний. `data_pipeline` собирает новости,
готовит профили компаний и платёжные показатели; `ai_engine` извлекает факты,
оценивает влияние и сохраняет основания анализа; `api` связывает модули и
обслуживает веб-интерфейс.

## Состав

- **Data pipeline:** загрузка и дедупликация новостей, профили и связи
  компаний, расчёт экспозиции, поиск по банковским отчётам.
- **AI engine:** извлечение проверяемых фактов, оценка `KEEP` / `REVIEW` /
  `DROP`, анализ рисков и возможностей, адаптация анализа по уточнению.
- **API и UI:** выбор компании и события, фоновые задачи с прогрессом,
  источники, ограничения и пользовательские уточнения.

## Локальный запуск

Нужен Python 3.11+. Установите приложение и зависимости API, UI и тестов:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

Укажите `LLM_API_KEY` в `.env`, если нужен полноценный анализ. Таймаут по
умолчанию — 180 секунд, лимит ответа — 8000 токенов. Таймаут запроса не
повторяется; `LLM_MAX_RETRIES` ограничивает повтор других временных ошибок.

Исходные CSV кейса не хранятся в репозитории. Положите их в `data/raw/`:

- `df_Uid_data_hack.csv`
- `df_Uid_payment_hack.csv`
- `df_Fid_Uid_link_hack.csv`

Соберите базу компаний и загрузите новости:

```powershell
python -m data_pipeline build
python -m data_pipeline news-fetch --max-items 30
```

Запустите веб-приложение:

```powershell
python -m uvicorn api.main:app --reload
```

UI: `http://127.0.0.1:8000/`; интерактивная схема API: `http://127.0.0.1:8000/docs`.
OCR-фрагменты банковских отчётов уже включены в `data/bank_reports/ocr/` и
доступны без LLM-вызова.

## Сквозной сценарий

1. Выберите компанию и событие в интерфейсе.
2. API проверит ID и запустит `process_news`, который извлекает и сохраняет факты.
3. Затем `analyze_company_impact` вернёт персональный разбор с источниками и
   ограничениями. Прогресс и итог доступны через `GET /api/v1/jobs/{job_id}`.
4. При необходимости отправьте уточнение: оно пересмотрит затронутые выводы и
   останется помечено как неподтверждённое утверждение пользователя.

API подключает репозитории `data_pipeline` к существующему сервису `ai_engine`;
новые очереди для анализа не создаются. Статусы обработки (`queued`, `running`,
`partial`, `completed`, `failed`) отделены от бизнес-класса события.

Маршруты и конфигурация описаны в [api/README.md](api/README.md), границы
модулей — в [docs/INTEGRATION.md](docs/INTEGRATION.md), подготовка данных — в
[docs/DATA_PIPELINE.md](docs/DATA_PIPELINE.md).

## Проверка

Чтобы установить зависимости тестового окружения, из корня проекта выполните:
```powershell
python -m pip install -e ".[dev]"
```

Затем запустите
```powershell
python -m unittest discover -s tests -t .
```

Тесты используют временные SQLite базы и фиктивные ответы LLM; сетевые
вызовы к модели не выполняются. Переменные `DATA_DB_PATH`, `NEWS_DB_PATH`,
`INTEL_SQLITE_PATH` и `API_JOBS_DB_PATH` позволяют указать отдельные базы.
